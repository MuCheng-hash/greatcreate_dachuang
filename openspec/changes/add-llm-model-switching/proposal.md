## Why

教学方案生成和智能问答当前只能使用服务端默认模型，教师无法根据质量、速度或成本选择已配置的模型。系统需要提供安全的请求级模型切换，同时保留现有故障回退能力和默认行为。

## What Changes

- 提供经过服务端白名单过滤的可用聊天模型列表，并标识默认模型。
- 教学方案生成和智能问答请求可携带模型标识；未选择时继续使用默认模型。
- LLM 服务优先调用用户选择的模型，并在失败时按配置顺序回退到其他模型。
- 教学方案和智能问答页面增加模型选择控件，展示模型名称、提供方及默认状态。
- 流式事件和最终响应继续返回实际执行的模型信息，使用户能够识别回退结果。
- 拒绝未知或未启用的模型标识，客户端不能提交模型地址、密钥或其他连接参数。

## Capabilities

### New Capabilities

- `llm-model-selection`: 定义可用模型发现、请求级模型选择、安全校验、故障回退及实际模型回显。

### Modified Capabilities

无。

## Impact

- `llm-service` 的请求模型、模型网关、Agent 运行时及模型列表接口。
- `business-service` 的 LLM 客户端 DTO、教学方案和问答接口转发。
- `business-service/frontend` 的教学方案页、智能问答页、API 类型和模型选择状态。
- Python、Java 与前端测试需要覆盖默认模型、指定模型、非法模型和回退场景。
