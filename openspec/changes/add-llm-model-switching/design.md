## Context

系统由 Vue 前端、Spring Boot 业务服务和 FastAPI LLM 服务组成。LLM 服务已从配置构建按优先级排列的模型链，并支持失败回退和实际模型元数据，但当前所有请求固定从链首开始。教学方案与智能问答都通过业务服务转发到统一 Agent 请求，因此模型选择必须跨三层传递，并且不能暴露连接地址或密钥。

## Goals / Non-Goals

**Goals:**

- 让教师在教学方案和智能问答页面按请求选择已配置模型。
- 由 LLM 服务提供单一、脱敏的模型目录，并负责选择校验。
- 选择模型失败后仍可使用其余配置模型回退。
- 保持不携带选择字段的旧客户端行为不变。
- 在流式事件和最终结果中回显实际执行模型。

**Non-Goals:**

- 不允许用户动态添加模型、API 地址或密钥。
- 不持久化每个用户的模型偏好，也不改变全局默认模型。
- 不改变嵌入模型、资源发现模型或管理员配置方式。
- 不按模型实施新的权限、配额或计费策略。

## Decisions

1. 使用稳定的服务端模型 ID，而不是把 provider/model 组合直接作为选择参数。模型 ID 从配置角色与模型名生成并由目录接口返回，LLM 服务将其解析到已加载目标。这样可以防止客户端注入任意连接配置，也避免同名模型跨提供方冲突。备选方案是直接传模型名，但无法可靠区分同名目标。

2. 在 LLM 服务提供 `GET /models` 脱敏目录，由业务服务以同源 `/api/ai/models` 转发给前端。目录只包含 ID、显示名、provider、model 和默认标志。前端不直接调用 FastAPI，以复用现有认证和部署拓扑。

3. 在统一 Agent 请求增加可选 `modelId`，业务服务的问答和教学方案 DTO 原样传递。未提供时从完整模型链开始；提供时将所选目标移到本次尝试链首，其余目标保持配置顺序且不重复。因此选择不会改变共享网关状态，也保留降级能力。

4. 非法 `modelId` 在 LLM API 边界返回 422，业务服务映射为可读的客户端错误。模型目录暂时不可用时，页面保留“系统默认”选项，旧流程仍可工作。

5. 两个页面分别在本地状态保存选择。智能问答在同一会话中的后续消息继续使用当前控件选择；切换只影响之后发送的消息，不追溯修改历史消息。

## Risks / Trade-offs

- [模型配置在页面打开后变化导致旧 ID 失效] -> 请求边界重新校验并提示用户刷新模型列表。
- [用户选择的模型失败后实际执行模型不同] -> 保留回退事件，并在最终结果区域显示实际模型。
- [目录接口短暂失败阻断核心功能] -> 前端回退到系统默认选项，选择字段保持为空。
- [共享网关的模型顺序被并发请求污染] -> 每次请求构造不可变的尝试列表，不修改全局 `chat_models` 顺序。

## Migration Plan

先部署兼容可选字段和目录接口的 LLM 服务，再部署业务服务转发，最后发布前端控件。所有字段均可选，任一步回滚后旧的默认模型路径仍然有效。

## Open Questions

无。模型展示名称先使用配置中的模型名；未来若需要面向教师的别名，可在服务端配置中增加独立标签字段。
