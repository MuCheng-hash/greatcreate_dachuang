## Why

现有智能问答只保留会话历史，无法在新会话中自动延续教师偏好和阶段任务，教学方案也不能复用已确认的用户画像。需要增加由用户主动开启、账号与学校双重隔离且可完整管理的跨会话记忆，同时避免把推断内容、敏感信息或记忆内容误当成学校事实与权限依据。

## What Changes

- 在现有 Agent SQLite 中持久化记忆设置、稳定画像、阶段任务和无正文审计记录，并通过仓库接口保留未来迁移能力。
- 记忆功能由全局开关和用户开关共同控制，均默认关闭；关闭用户开关时保留数据，但停止提取、召回和注入。
- 明确的“记住……”指令直接保存，普通对话推断仅生成最多三条待确认候选；模型降级时不产生推断候选。
- 在智能问答和教学方案中注入已确认的稳定画像及最多五条相关阶段任务，并限制总长度；当前输入和可信业务上下文始终优先。
- 提供设置、列表、新建、编辑、确认、删除、恢复和永久删除接口，以及待确认、已生效和回收站的完整记忆中心。
- 为问答响应增加可选的 `memoryCandidates` 和 `memoryApplied` 字段，保持现有普通响应和 SSE 客户端兼容。
- 对账号、学校和平台管理员实施正文访问隔离，并拒绝保存密码、令牌、密钥、身份证号、电话和精确住址等敏感内容。
- 稳定画像不过期，阶段任务保留 90 天，待确认候选保留 7 天，删除后进入 30 天回收站并支持恢复或提前永久删除。
- 资源发现与资源审核流程保持不变，不引入向量库、Embedding 或 RAG。

## Capabilities

### New Capabilities

- `cross-session-user-memory`: 定义记忆启用、提取与确认、跨会话召回、教学方案应用、生命周期管理、敏感信息保护、访问隔离和兼容响应。

### Modified Capabilities

无。

## Impact

- `llm-service` 的 SQLite 仓库、Agent 运行时、结构化任务上下文、FastAPI 路由、配置和响应模型。
- `business-service` 的 Agent 客户端、登录态派生的记忆代理接口、DTO 和聚合指标边界。
- `business-service/frontend` 的个人中心记忆管理、智能问答候选确认卡片和记忆使用标识。
- Python、Java、Vitest、前端生产构建及真实页面验收流程。
- 新功能全局默认关闭，按 FastAPI、Spring、前端顺序部署；现有接口仅增加可选字段，无破坏性协议变更。
