## Why

当前跨会话记忆在确认、恢复、手动新增或编辑字段时，会在后端静默把同一字段键的已生效记忆移入回收站。前端确认成功后只插入新条目，未同步被替换的旧条目，导致用户在刷新前看到彼此冲突的值、刷新后又发现旧值消失。这既降低了可解释性，也让用户无法选择保留已有偏好。

## What Changes

- 将同一账号、学校范围和规范化字段键下的已生效记忆冲突改为显式处理，不再静默覆盖。
- 为待确认记忆提供确认预检；返回候选、冲突项和完全重复标记。
- 扩展确认接口：无冲突直接生效；存在冲突时必须显式选择替换，否则返回无副作用的冲突结果。
- 将“替换旧值”“保留旧值”“取消”的状态迁移固定为：替换时旧项进入 30 天回收站；保留时新候选进入回收站；取消时候选保持待确认。
- 让确认、恢复、手动新增及修改字段都复用相同冲突规则，并在 Vue 中提供项目内冲突弹窗和即时列表同步。
- 统一回答格式字段为 `answer_format`，兼容历史 `response_format` 别名，不做批量数据删除或改写。

## Capabilities

### New Capabilities

- `memory-conflict-resolution`: 定义跨会话记忆的冲突预检、用户决策、重复处理、原子状态迁移、作用域隔离和前端可解释交互。

### Modified Capabilities

- `cross-session-user-memory`: 修改同字段核心画像的激活规则，由自动替换改为显式冲突处理。

## Impact

- 影响 `llm-service` 的 `MemoryRepository`、FastAPI 记忆路由及 Python 回归测试。
- 影响 Spring 的记忆代理 DTO、运行时客户端和 Controller 测试；浏览器仍不能传递所有者或学校范围。
- 影响智能问答与个人中心的 Vue 记忆确认流、弹窗组件和 Vitest。
- 不修改现有 SQLite 表结构、记忆生命周期、SSE 响应或历史快照。
