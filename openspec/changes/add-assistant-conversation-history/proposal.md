## Why

智能问答虽然已经在 LLM 服务中持久化线程和消息，但前端只记住当前浏览器会话，用户无法查看此前对话或从历史上下文继续提问。需要将现有服务端会话数据转化为按账号隔离、可回看和可恢复的历史记录功能。

## What Changes

- 按已认证用户列出其智能问答历史线程，按最近更新时间倒序展示。
- 为历史线程生成稳定的展示标题和最后一条消息预览，不额外调用 LLM。
- 支持读取某个历史线程的完整用户/助手消息并恢复到问答界面。
- 选择历史线程后，后续问题继续发送到原 `threadId`，保留上下文。
- 支持从界面新建空白对话，并继续保留历史记录。
- 支持归档历史对话，使其从活动历史列表中移除。
- 所有历史查询、读取和归档均验证线程所有者，不允许跨账号或跨学校访问。

## Capabilities

### New Capabilities

- `assistant-conversation-history`: 定义智能问答历史列表、消息回看、继续对话、新建对话、归档和访问隔离。

### Modified Capabilities

无。

## Impact

- `llm-service` 的线程仓库、线程 API 和响应结构。
- `business-service` 的 Agent 客户端、认证后的问答历史接口和 DTO。
- `business-service/frontend` 的智能问答历史侧栏、消息恢复与会话切换状态。
- Python、Java 和前端测试覆盖排序、标题、所有权隔离、恢复、续聊和归档。
