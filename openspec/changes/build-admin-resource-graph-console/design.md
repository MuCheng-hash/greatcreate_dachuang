## Decisions

1. MySQL 是资源、实体、关系、媒体和来源的事实源。Neo4j 与 RAG 只消费审核通过且启用的数据。
2. 审核通过的记录被编辑后回到 `pending`；删除为逻辑停用。关联两端或任一关系未发布时，不投影图谱边。
3. 图谱关系仅复用现有关系表和枚举，禁止客户端传入任意关系名。
4. Excel 使用一个多工作表 `.xlsx`，预检结果保存为短期批次记录；确认只导入校验通过且未重复的行，导入记录一律 `pending`。
5. 投影失败不回滚已保存的待发布数据，保留可重试任务且不将失败记录对外发布。
6. 资源工作表保留现有多工作表模板兼容性，模板展示资源名称、资源类型、行政区域、地址、经纬度、简介、教育价值、数据来源和适合学段；导入器同时识别新旧列名并按表头定位字段。
7. 资源工作表的编码、名称、类型、行政区域、地址、经度、纬度、简介、教育价值、数据来源和适合学段均为必填；其他实体工作表继续只要求编码和名称。行政区域按 ID、名称或 adcode 解析，坐标按数值和经纬度范围校验。
8. 预检使用实体类型加编码进行工作簿内和数据库重复检查，确认时再次检查以处理预检后的并发变化；编码继续作为唯一标识，不新增重复判定表。
9. 关系预检同时解析工作簿实体和数据库实体，并复用关系方向与类型白名单。确认时合法关系写入现有关系表但不立即投影；实体审核通过时仅在关系两端都已发布后创建 Neo4j/RAG 投影任务。
10. 数据来源复用现有来源关联字段保存，关系导入复用现有关系表和外键，不增加数据库表或导入行结构。

## Migration

- 新增导入批次、导入行和投影任务表，并更新全量与一次性 MySQL 脚本。
- 应用不在启动时执行迁移；部署先执行 SQL，再启动应用。
