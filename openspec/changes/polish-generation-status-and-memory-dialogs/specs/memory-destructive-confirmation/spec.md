## Purpose

为长期记忆和用户画像的破坏性操作提供与工作台视觉一致、可访问且能清楚说明数据影响的确认体验，避免依赖浏览器原生提示框；同时让待确认的推断记忆获得清晰、就近的处理入口。

## ADDED Requirements

### Requirement: 破坏性记忆操作使用工作台确认界面
系统 SHALL 在单条移入回收站、永久删除和清空当前列表或回收站前展示工作台内确认界面；取消确认时不得发起删除请求。

#### Scenario: 确认单条移入回收站
- **WHEN** 用户点击已生效记忆的删除操作
- **THEN** 系统展示说明立即失效和 30 天回收期限的确认界面，并仅在用户确认后移入回收站

#### Scenario: 确认永久删除
- **WHEN** 用户点击回收站记忆的永久删除操作
- **THEN** 系统展示不可恢复的确认界面，并仅在用户确认后永久删除该记忆

#### Scenario: 确认清空当前列表
- **WHEN** 用户点击清空当前列表或清空回收站
- **THEN** 系统展示固定的目标数量和对应操作，并仅在用户确认后处理该批目标

### Requirement: 确认界面支持安全取消和键盘访问
确认界面 SHALL 提供取消操作，并支持 Esc 与点击遮罩取消；确认执行期间 SHALL 防止关闭和重复提交，关闭后焦点 SHALL 返回原触发操作。

#### Scenario: 用户取消危险操作
- **WHEN** 用户点击取消、按 Esc 或点击遮罩
- **THEN** 确认界面关闭、焦点回到触发按钮，且记忆数据不发生变化

#### Scenario: 确认请求处理中
- **WHEN** 用户确认一项破坏性操作且请求尚未完成
- **THEN** 系统禁用取消、遮罩关闭和重复确认，直至请求成功或失败

### Requirement: 待确认记忆在输入区集中呈现
系统 SHALL 将当前会话内所有状态为 `pending` 的记忆候选展示在智能问答输入框上方的常驻操作区，而不得将候选卡片混入回答的来源或追问区域。每条候选 SHALL 显示类型、内容和直接可用的确认、忽略操作；回答中的已应用记忆数量 SHALL 保持原有展示。

#### Scenario: 收到多个待确认候选
- **WHEN** 当前会话的一个或多个回答返回待确认记忆候选
- **THEN** 输入区上方显示候选总数和全部候选卡片，且每张卡片仍关联其所属回答

#### Scenario: 成功处理候选
- **WHEN** 用户确认或忽略一条候选且既有记忆 API 请求成功
- **THEN** 系统从输入区立即移除该候选，在输入区显示成功提示 5 秒后自动隐藏；若没有剩余候选，焦点 SHALL 回到问答输入框

#### Scenario: 新反馈替换旧成功提示
- **WHEN** 成功提示尚未自动隐藏，用户再次处理候选或离开当前会话
- **THEN** 系统取消旧提示的计时，避免旧回调影响新的成功或失败反馈

#### Scenario: 候选处理失败
- **WHEN** 用户确认或忽略一条候选但既有记忆 API 请求失败
- **THEN** 系统保留该候选，并在输入区显示失败原因

#### Scenario: 恢复历史或归档对话
- **WHEN** 用户打开历史对话或归档对话
- **THEN** 系统恢复已有回答结果但不从历史元数据重新生成待确认候选卡片
