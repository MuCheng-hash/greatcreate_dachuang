## Context

参见 `proposal.md`。智能问答和教学方案已从 SSE 事件中接收实际模型信息，并将该信息保存在前端状态和历史快照中。记忆中心目前在三类破坏性操作前调用浏览器原生确认框，项目没有通用弹窗组件。智能问答收到推断记忆候选后，原先将卡片放在对应回答的末尾；长回答、来源和追问会使其不易被注意到。

## Goals / Non-Goals

**Goals:**

- 将实际模型信息限定为生成中的临时状态，不破坏诊断和持久化元数据。
- 用一个可复用、无第三方依赖的确认弹窗替换记忆中心现有原生确认框。
- 将当前会话尚未处理的推断记忆集中显示在输入框上方，并保留候选所属回答以继续调用既有确认、忽略和移除逻辑。
- 保持现有记忆 API、生命周期、权限和错误提示逻辑不变。

**Non-Goals:**

- 不删除后端响应或 SQLite 快照中的 `provider/model` 字段。
- 不为“忽略候选记忆”新增确认步骤，也不扩展至当前没有原生确认框的页面。
- 不引入全局状态管理、第三方弹窗库或后端迁移。
- 不将候选记忆写入历史快照，不在历史恢复、归档对话或新会话中重新生成候选卡片。

## Decisions

1. 模型提示的可见性由现有“仍在生成”状态决定，而不是清空 `effectiveModel`。这样最终和历史界面不会显示文案，同时保留模型信息供执行轨迹、调试和持久化元数据使用；删除模型字段会降低可观测性。

2. 新增独立确认弹窗组件，以遮罩层和工作台已有的色彩、按钮、圆角和阴影令牌呈现。组件通过受控的打开状态、标题、说明、确认文案和危险级别工作，不直接调用记忆 API；这使其可在后续页面复用而不引入全局依赖。

3. 记忆中心在弹窗打开时保存不可变的操作描述和目标快照。单条操作保存目标记忆，批量操作保存当时的目标列表和数量，确认后才调用原有删除服务；该方式避免弹窗停留期间状态切换造成目标漂移。

4. 弹窗默认把焦点置于取消按钮，使用 `role="alertdialog"`、明确的标题和说明关联，并在打开期间限制 Tab 焦点在弹窗内。Esc、遮罩和取消均视为安全取消；请求处理中禁用这些退出途径，成功后关闭并恢复触发元素焦点。

5. `AssistantView` 从当前内存中的回答消息汇总 `pending` 状态的候选，并保留“候选—所属回答”配对。候选只在输入框上方的常驻区域渲染，不再混入回答、来源或追问区域；`memoryApplied` 仍属于回答结果并维持原位置。

6. 确认或忽略继续调用现有记忆 API。成功后只从原回答的候选列表移除对应项目，并在输入区显示结果；失败时不移除候选而在同一区域显示错误。最后一条候选成功处理后，等待 DOM 更新并把焦点交还给输入框，方便继续提问。

7. 输入区的成功反馈使用组件本地的单一定时器，在显示后 5 秒自动清除；显示下一条反馈、清空会话或卸载组件时先取消旧定时器，避免过期回调误清除新反馈。错误反馈不自动消失，确保用户能看到失败原因。

## Risks / Trade-offs

- [手工焦点管理遗漏边界情况] → 为 Esc、遮罩、Tab 循环和触发焦点恢复补充组件与集成测试。
- [确认异步失败后用户误判结果] → 失败时保持弹窗打开、恢复操作按钮并显示错误信息；成功才关闭。
- [模型提示被误当成最终内容] → 只修改渲染条件，不修改 SSE、响应 DTO 或快照字段。
- [待确认候选随长回答滚出视野] → 将候选区域放在固定的输入区上方，按钮直接可用，并在移动端改为纵向排布。
- [历史记录错误地重放待确认候选] → 历史映射不读取候选字段，汇总数据仅来自当前内存会话的待确认项。

## Migration Plan

1. 部署前端组件和视图变更，无需数据库或接口迁移。
2. 构建 Vite 静态产物并重启 Spring 后刷新页面验证。
3. 若需回滚，仅回退前端产物；候选仍由原有 API 管理，现有原生确认与模型元数据不会产生数据兼容问题。
